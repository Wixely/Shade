## Implemented in this continuation

Screen intent now persists separately from effective opacity in version 3 settings: global percentage, per-screen enabled state, global membership and independent level, plus explicit screen assignments. Trusted disconnected screens retain intent; a returning linked screen uses the latest global percentage. Emergency recovery clears connected and disconnected enabled intent, including at 0%. Version 1 migrates to independent screen controls to preserve existing levels without inventing membership; version 2 preserves those controls. Corrupt/unknown-version files remain preserved. Geometry remains separate from identity.

Advanced now offers named assignments for ambiguous screens, reusable disconnected assignment slots and detach. Reassignment retains the durable ID and independent settings but starts undimmed. An occupied assignment cannot be silently moved. These are explicit connection mappings, not a claim to infer physical identity from missing serial information. The settings recovery button preserves the exact unreadable file in a backup and rolls back the move if saving the replacement fails.

Global changes now send one backend batch for enabled, linked screens. Windows resolves all targets before applying and publishes one snapshot; Linux sends one worker request and synchronizes X once. Unchanged Windows batches do not call native shading or publish. This reduces thread/pipe crossings and snapshot publications without changing the disabled/global exclusion rules; game frame-time evidence remains required.

Home Assistant setup is available through the header button, replacing the scrolling screen list with a settings view and a Back to screens action: hostname, port, username, masked password, TLS, test, save/enable, disable, forget saved password and discovery removal. Windows protects saved passwords with current-user DPAPI in the private application settings directory. Blank password input keeps an existing credential; forgetting it disables the integration and removes the saved secret. Linux now uses a libsecret-backed encryption key and authenticated encrypted settings, with native keyring acceptance still outstanding; encrypted Windows credentials are not portable.

The initial automation transport uses MQTT 5 through pinned MQTTnet. Discovery creates a global dimming number, and an enabled switch, use-global switch and dimming number per trusted display. All numbers use 0–80% dimming directly, avoiding a light brightness inversion. Retained commands are rejected, including live retained publishes using MQTT 5 retain-as-published. Clean sessions prevent an offline command backlog. Retained discovery/state, installation-plus-monitor IDs, individual availability, last will, Home Assistant birth republishing, bounded command buffering and automatic reconnect are implemented. Individual commands use the same screen-control model as local UI interactions. Network work runs asynchronously; state publications are coalesced and unchanged values are suppressed.

Disabling leaves entities unavailable; removal also clears retained discovery. A broker failure preserves local dimming. Fresh installation IDs deliberately create Shade entities, with no legacy configuration import or entity migration.

TLS trust follow-up, 2026-09-10: the self-contained Linux test executable now runs six independent child processes against loopback TLS brokers using the production `HomeAssistantIntegration.TestAsync` path and default certificate validation. A generated root is selected only through each child's OpenSSL trust environment. A signed, locally served certificate revocation list supplies the revocation information required by the pinned MQTTnet client's default policy. No validation bypass or production TLS change was introduced.

- Trusted, correctly named, currently valid certificate: connection test succeeds; exactly one MQTT CONNECT reaches the broker.
- Wrong hostname, expired, not-yet-valid, untrusted and revoked certificates: each connection test fails; zero MQTT application streams or CONNECT packets reach the broker.
