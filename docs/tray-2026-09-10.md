# Tray lifecycle

- Status: Windows close/restore/exit implemented and tested in GPU and software previews
- Owner: Codex
- Reviewed: 2026-09-10; next review: 2026-09-17

Shade opts into the pinned CupriFace 0.20.0 Windows tray implementation. The released assembly was inspected to confirm the `CloseToTray` and `TrayCloseLabel` APIs before using them. No dependency update or new native tray implementation was introduced.

Closing the Windows control window hides it while shading and automation remain active. Clicking the tray icon restores the window. Its native menu offers opening the controls and **Exit Shade**; exit returns from the desktop host so the existing program disposal order removes overlays before awaiting MQTT shutdown. Restore-all remains available through Ctrl+Alt+Shift+R and the control-window button; the pinned tray menu has no custom restore command. The UI footer explains the changed close behavior. `--no-tray` restores ordinary close-to-exit operation.

Linux keeps normal window-close behavior because this host version implements the tray only on Windows. Linux tray support remains required work and is not inferred from these tests.

## Evidence

Live Windows GPU and software previews passed close-to-tray (process remains alive, window hidden), tray activation (window visible), native-menu exit and zero process exit code. The preview uses a fake shading backend and does not load settings or disturb the existing user app. The same run verified all seven sliders, form accessibility and 0 ms process CPU in a five-second idle sample. The combined Windows suite still passes 23 checks.

The native popup's menu item was not exposed through UI Automation in this environment. The test locates only the popup owned by its process, verifies the final item's label and native bounds, confirms that its app owns foreground focus, then clicks that item. It restores the cursor afterward, including failure cleanup. Posting keyboard messages did not activate the menu and is not counted as passing evidence.

```powershell
.\scripts\smoke-ui.ps1 -Configuration Release -Preview -Tray -Software
.\scripts\smoke-ui.ps1 -Configuration Release -Preview -Tray
```

A subsequent `--hidden-mqtt` check passed in both GPU and software hosts. It launches the real CupriFace host with two small native overlay rectangles and a separate recovery key, then hides the control HWND with the same ShowWindow operation used by the tray implementation. A loopback MQTT client verifies global changes, disabled-screen exclusion, individual opt-out, native opacity, state republishing and emergency recovery while hidden. The driver never reads model revision or explicitly refreshes bindings: the live host must process the commands. It reopens the control window, enables a native overlay, closes the host and verifies that every captured native overlay HWND is destroyed after backend disposal.

```powershell
dotnet run --project tests/Shade.Tests -c Release -- --hidden-mqtt
# Repeat with CUPRIFACE_SOFTWARE=1 for the software host.
```

The hidden-MQTT fixture uses ordinary close-to-exit to keep shutdown deterministic; the separate preview checks above cover the actual tray menu callback. The packaging continuation additionally verified actual tray hide/restore/exit in a published self-contained executable using the native Windows backend. Its script now uses per-monitor DPI awareness when reading menu geometry and positioning/restoring the cursor; earlier mixed-DPI menu-click failures remain in the evidence record. Explorer restart, tray-shell failure, Linux tray behavior and full accessibility acceptance still require Codex verification.
