# Keyboard navigation verification

- Reviewed: 2026-09-10; next review: 2026-09-17
- Owner: Codex

The patched Cupri engine reveals controls reached by Tab/Shift+Tab and paints their focus outline using scrolled, clipped bounds. Shared tests cover movement on both axes, reverse traversal and wraparound. Published Linux native event checks cover broker fields and actions on default and software hosts. See [engine provenance and evidence](../third-party/CupriFace.Engine/README.md).

Windows now has a matching opt-in check:

```powershell
.\scripts\smoke-ui.ps1 -KeyboardNavigation -ExecutablePath <published-Shade.exe> -EvidenceDirectory <fresh-directory>
```

Use `-Software` for SDL software rendering. `-Capture` also selects software rendering and saves Cupri debug frame readbacks under the ignored evidence directory.

The test sets initial focus to Broker hostname, then sends native Tab key messages to the owned window through Broker port, Use TLS, Broker username, Broker password, Forget saved password, Test connection and Save and enable. Shift+Tab returns along the same sequence. Each step must expose the expected UI Automation keyboard-focus state and bounds inside the content viewport. The geometry assertion accounts for the window's DPI and physical client position. The test never activates the navigated action buttons. Existing slider/set/restore and masked-password typing checks still run first.

The published untrimmed Windows single-file app passes on software and default GPU renderers, including normal exit. These native-message checks do not cover all physical keyboard layouts, IMEs, assistive technologies or OS-level focus switching. Windows UIA still lacks the explicit IsPassword flag; its tested password value remains masked. That is a separate open accessibility issue.

The software capture run also passes. Its fresh Cupri frame was inspected: the lower broker actions are visible, the outline surrounds Test connection, and the password remains masked. Capture alternates native keyboard focus between adjacent actions to produce presentations without activating either action; it does not use background clicks that would clear keyboard focus. Build validation completes with no warnings or errors.

## Password semantics follow-up, 2026-09-10

The missing IsPassword finding above is now addressed by the [Windows password patch](../third-party/CupriFace-Shell-windows-password.md). The live test checks the flag before and after typing, rejects default-substituted value reads as insufficient evidence, and verifies protected reads are unavailable while normal text remains readable. Native keyboard navigation still passes. Complete UIA Text/programmatic editing and real screen-reader acceptance remain open.
